# PlatformIO IDE 识别系统 Core 的修复

## 根因
扩展(useBuiltinPIOCore=false 时)的检测链:在 customPATH+PATH 中找 `python3` → 用它跑 `check core --global`(要求 PATH 里有 `platformio` 且**该 python 能 `import platformio`**,版本 ≥6.1.6)。当前系统没有 python3,nixpkgs 的 platformio 又是 FHS 包装(模块对外不可见),检测必败。

## 改动

**modules/cli/platformio.nix**:
1. `environment.systemPackages` 中 `pkgs.platformio` 替换为 `(pkgs.python3.withPackages (ps: [ ... ]))`——环境 bin 同时提供 python3 / pio / platformio,检测四条件全满足,IDE 与命令行共用同一套
2. python 包属性名构建时用 eval 验证(`python3Packages.platformio` 或 `platformio-core`),以实际存在的为准
3. udev 规则块原样保留

**验证**:
- `nix eval` toplevel 零错误零警告
- 构建该 python 环境,运行其中 `python3 -c "import platformio; print(platformio.__version__)"` 确认 6.1.19 且可导入

**用户侧**:settings.json 无需再改(customPATH/useBuiltinPIOCore 已正确);`nh os switch` 后 reload VSCode 窗口,PlatformIO 即用系统 Core。

## 风险与后续
- 下载的交叉工具链(动态链接)由已启用的 nix-ld 运行;个别工具链报缺 .so 时往 `programs.nix-ld.libraries` 补
- `disablePIOAutoInstall` 非有效设置名(机制由 useBuiltinPIOCore 控制),无害,可留
